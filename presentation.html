SPEAKER 1: ALGORITHMIC FOUNDATION (1:15 - 2:15)

Theoretical Foundation: MST & The Cut Property

The Cut Property (Greedy Core)
  • Cut Definition: Any partition dividing vertices into sets S and V \ S.
  • Invariant: The minimum-weight edge crossing the cut belongs to the MST.
  • Greedy Choice: At each step, Prim's grows a tree T from a seed hub by picking the cheapest crossing edge (u ∈ T, v ∉ T).
  • Optimality Proof: Proven mathematically via cut-crossing exchange arguments.
Spanning Tree Properties in Telecom
  • Exactly |V| - 1 Cables: An 8-city grid requires exactly 7 optical connections.
  • Acyclic Guarantee: Zero routing loops, preventing optical broadcast storms.
  • Start-Node Invariance: Starting from Central Metro, North Gateway, or Kochi produces identical total cost.
  • Global Cost Minimization: sum(w_e) is minimized across all 2^E spanning subgraphs.
SPEAKER 1: ALGORITHM SELECTION (2:15 - 3:00)

Prim's vs. Kruskal's: Why Prim's for Telecom?

  • Deployment Realism: Optical cables are physically laid outward from an established central telecom hub (Hub-and-Spoke expansion). You don't deploy disjointed cables in isolated towns before connecting the core.
  • Vertex-Centric Growth: Prim's expands outward from a single active exchange point, matching telecom civil trenching logistics.
  • Dense Network Advantage: In dense urban regional meshes (E ≈ V²), Prim's achieves O((V + E) log V), outperforming Kruskal's global edge-sorting step.
  • Data Structure Paradigm: Uses a Min-Priority Queue (Binary Heap) tracking crossing cables, contrasted with Kruskal's Disjoint-Set Union (Union-Find).
  • Handoff: Speaker 2 will now explain how our application translates this mathematical engine into a deterministic single-screen visualizer.

SPEAKER 2: CORE ENGINE (4:00 - 5:15)

Core Engine: Min-Priority Queue & Snapshots

Binary Min-Heap Implementation
  • Custom MinHeap Class: Stores candidate optical edges: { edgeId, u, v, w }.
  • Push (Enqueue): O(log N) bubble-up preserving heap parent invariant.
  • Pop (Extract-Min): O(log N) bubble-down retrieving the cheapest cable.
  • Non-Destructive Inspection: getSortedItems() provides sorted live preview for the UI without altering heap order.
Immutable Snapshot Schema
  • step & action: Tracks phase ('startVisit', 'popMin', 'addToMst', 'skipVisited').
  • status: Drives visual color states ('candidate', 'considered', 'added', 'rejected').
  • cityOrder: Chronological arrival sequence tracking cities #1 to #V.
  • activeLine: Synchronizes code highlighting across JS, Python, C++, and Java.

SPEAKER 3: ENGINEERING BREAKTHROUGHS (6:30 - 7:45)

Key Technical Challenges & Solutions

1. SVG Filter Zero-Area Bug
  • Problem: Perfectly vertical cables (x1 === x2, Central Metro to North Gateway) vanished from screen.
  • Cause: SVG objectBoundingBox filter calculates 0-width area, discarding all pixels.
  • Fix: Replaced inline SVG filters with CSS drop-shadow, guaranteeing 100% stroke visibility.
2. Radial Spoke Symmetry
  • Problem: Regional Mesh had missing cross-connect cables to West Valley (N7) and Northeast Tech (N3).
  • Fix: Engineered e13 (20 km) and e14 (23 km), completing full radial spoke mesh connectivity.
  • Balanced geometry on 700x480 canvas with zero label overlap.
3. Responsive Viewport
  • Decoupled panel scrolling (Visualizer locked at 100vh, Theory & Quiz smoothly scrollable).
  • Breakpoints at 1240px, 1040px, and 820px preventing top-bar control overflow.
  • Dropdown text truncation with ellipsis ensuring clean presentation on any screen.
SPEAKER 3: ASYMPTOTIC COMPLEXITY (7:45 - 8:30)

Asymptotic Complexity & Test Verification

Time Complexity: O((V + E) log V)
  • Adjacency List Construction: O(V + E) upfront mapping.
  • Heap Insertions: At most 2|E| insertions -> O(E log V).
  • Heap Extractions: Extract-min for each crossing candidate -> O(E log V).
  • Sparse Telecom Reality: In real road/railway grids (E = O(V)), runtime reduces to O(V log V).
Space Complexity & Unit Tests
  • Space Complexity: O(V + E) for Min-Heap, visited set, and snapshot arrays.
  • Disconnected Detection: Gracefully identifies island components and yields a Spanning Forest.
  • Automated Test Suite: 12/12 unit tests passing in Node.js verifying heap integrity, invariance, and line mappings.
